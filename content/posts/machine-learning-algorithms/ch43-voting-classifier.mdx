## 1. Hard Voting vs Soft Voting

`VotingClassifier` takes a list of `(name, estimator)` pairs and a `voting` argument. That argument is the whole distinction:

- **`voting="hard"`**: each base model outputs a class label. The ensemble's prediction is whichever label got the most votes. This is exactly the majority vote from the last post.
- **`voting="soft"`**: each base model outputs a *probability* for each class (`predict_proba`). The ensemble averages those probabilities across models, then predicts whichever class has the higher average.

Concretely, for a binary problem with three base models predicting `P(class 1) = 0.2, 0.8, 0.6`:

- Hard voting only sees the labels each of those imply (`0, 1, 1`), so it votes **class 1**, 2 votes to 1.
- Soft voting averages the probabilities: `(0.2 + 0.8 + 0.6) / 3 = 0.53`, still **class 1**, but as a much closer call. If the third model had said `0.35` instead of `0.6`, hard voting would still land on class 1 (labels `0, 1, 0` → wait, that's a tie broken by the first-listed model in practice, but the point holds) while soft voting's average `0.45` flips to **class 0**. Soft voting is sensitive to *how confident* each model is, not just which side of 0.5 it landed on. That extra information is usually worth having, which is why soft voting tends to outperform hard voting, though not always.

Every base estimator used in soft voting must implement `predict_proba`. `LogisticRegression`, `KNeighborsClassifier`, and tree ensembles all do; a plain `SVC` needs `probability=True` (which internally fits an extra calibration step, so it's slower to train).

A few things worth actually testing here, not just reading:

This is condition 1 from the last post: independent errors get outvoted.
- On **Outlier**, watch what a single mislabelled/far-flung point does to each model's boundary individually versus what it does to the vote. KNN and the tree-based models bend hard around it; Logistic Regression barely notices; the ensemble sits in between.
- Switch **Concentric Circles** between hard and soft voting with Logistic Regression included. Its boundary is a straight line no matter what, so it's confidently wrong across roughly half the circle. Under soft voting that confident wrongness pulls the averaged probability further than a single vote would under hard voting, exactly the "soft voting is sensitive to confidence" point above, and here it's sensitive in the wrong direction.

## 3. `VotingClassifier` in scikit-learn

```python
from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import KNeighborsClassifier
from sklearn.ensemble import RandomForestClassifier, VotingClassifier
from sklearn.model_selection import cross_val_score

lr = LogisticRegression(max_iter=1000)
knn = KNeighborsClassifier()
rf = RandomForestClassifier(n_estimators=100, random_state=42)

estimators = [("lr", lr), ("knn", knn), ("rf", rf)]

hard_vote = VotingClassifier(estimators=estimators, voting="hard")
soft_vote = VotingClassifier(estimators=estimators, voting="soft")
```

`estimators` is a list of `(name, model)` tuples, not just a list of models, the same convention `Pipeline` uses. `cross_val_score` treats `hard_vote` and `soft_vote` like any other estimator:

```python
for name, model in estimators + [("hard voting", hard_vote), ("soft voting", soft_vote)]:
    print(name, cross_val_score(model, X, y, cv=10).mean())
```

Run on a moderately hard synthetic binary dataset (12 features, meaningful class overlap, `make_classification(class_sep=0.6)`), the three base models land well apart in skill, and voting sits above the pack:

Soft voting (0.791) edges out every individual model, including the best one (Random Forest at 0.787). Hard voting (0.777) actually falls *below* the best individual model here, a reminder that this is a real dataset with real correlated errors, not the idealised independent-70%-models arithmetic from the last post. Logistic Regression drags the hard vote down by throwing a full vote at every prediction even when it is barely better than a coin flip on this data; soft voting lets its low-confidence votes matter less.

## 4. Weights: Not Every Vote Has to Count the Same

By default every base model gets one equal vote. `VotingClassifier` accepts a `weights` argument to change that:

```python
VotingClassifier(estimators=estimators, voting="soft", weights=[1, 2, 3])
```

This means Random Forest's probability counts three times as much as Logistic Regression's when the votes are averaged. It is a hyperparameter like any other, searchable by brute force:

```python
from itertools import product

best = None
for w1, w2, w3 in product(range(1, 4), repeat=3):
    vc = VotingClassifier(estimators=estimators, voting="soft", weights=[w1, w2, w3])
    score = cross_val_score(vc, X, y, cv=5).mean()
    if best is None or score > best[1]:
        best = ((w1, w2, w3), score)
```

Run on a second synthetic dataset where the base models are more spread out in skill (`lr` at 0.749, `knn` at 0.851, `rf` at 0.867 individually), the top of a full 27-combination grid search over `weights=[w1, w2, w3] for w1, w2, w3 in 1..3`:

| Weights (lr, knn, rf) | CV accuracy |
|---|---|
| (1, 2, 3) | **0.878** |
| (1, 3, 3) | 0.876 |
| (1, 2, 2) | 0.873 |
| (1, 3, 2) | 0.872 |
| equal (1, 1, 1) | 0.860 |

The best weighting (0.878) beats equal weighting (0.860) by almost 2 points, and it makes intuitive sense: it downweights the weakest model (`lr`) and upweights the strongest (`rf`), roughly in proportion to how each actually performs. That is the general pattern, weight base models by how much you trust them, though which exact combination wins is still something you search for rather than guess.

## 5. Diversity Without Different Algorithms

Everything so far pairs up *different algorithms* to get independent errors. There is a second route: take **one algorithm**, fit it several times with **different hyperparameters**, and vote across those instead.

This is useful specifically when a hyperparameter is hard to pick by eye. An SVM's `degree` (for a polynomial kernel) is a good example, there is often no principled way to guess it upfront:

```python
from sklearn.svm import SVC

degrees = [1, 2, 3, 4, 5]
svm_estimators = [
    (f"svm_d{d}", SVC(kernel="poly", degree=d, probability=True))
    for d in degrees
]
vote = VotingClassifier(estimators=svm_estimators, voting="soft")
```

On a noisy two-moons dataset, held out test accuracy per degree, plus the vote across all five:

<img src="/images/ch43-hyperparam-diversity.png" alt="Bar chart of held-out test accuracy for five SVM models with polynomial kernel degrees 1 through 5, plus a voting ensemble across all five. Degree 1 scores 0.822, degree 2 scores 0.689, degree 3 scores 0.856, degree 4 scores 0.689, degree 5 scores 0.811, and Voting scores 0.844. The voting bar is coloured blue" className="w-full h-auto" />

Two things stand out. First, degree matters a lot here, degree 3 (0.856) beats degree 2 (0.689) by 17 points, and you would not know which one to pick without trying them all. Second, the vote (0.844) doesn't beat the single best degree (0.856), but it comfortably beats the *average* degree and, crucially, it is nowhere near the worst ones (0.689). If you had picked degree 2 or 4 blind, you would have a much worse model; voting across all five is a way to never be that unlucky, at the cost of a small amount of the best-case upside. Whether that trade is worth it depends on whether you can afford a proper hyperparameter search (grid search or similar) instead, in which case that usually wins outright, or whether you want a reasonable answer without one.

## 6. What to Take Away

- `VotingClassifier(estimators=[...], voting="hard" | "soft")`. Hard votes on labels, soft averages probabilities and is usually the better default when every base model supports `predict_proba`.
- `weights` lets stronger base models count for more; there's no formula for the right weights, only search.
- Diversity doesn't require different algorithms. The same algorithm at different hyperparameter settings works too, and is a decent hedge when you can't easily tell which setting is best.
- None of this is a guarantee. [Ch.42](/machine-learning-algorithms/ch42-voting-ensemble-intuition) already showed the failure mode: base models worse than random make voting worse, not better. In the numbers above, hard voting even a set of *good* models underperformed the best individual one, because their errors weren't as independent as the clean-probability math assumes.
