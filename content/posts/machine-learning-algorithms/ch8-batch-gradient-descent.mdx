In this post, we extend that same logic to the **multi-feature** case: $k$ input columns, $k+1$ parameters to learn simultaneously. ## From One Feature to Many: The Setup

In the previous post, the model had one slope $m$ and one intercept $b$. Every real dataset has more features. The diabetes dataset, for example, has 10 clinical measurements per patient. The general multiple linear regression model is:

$$\hat{y}_i = \beta_0 + \beta_1 x_{i1} + \beta_2 x_{i2} + \cdots + \beta_k x_{ik}$$

where $\beta_0$ is the intercept and $\beta_1, \ldots, \beta_k$ are the $k$ slope coefficients. For a dataset with $k$ input columns, you have $k + 1$ parameters to estimate.

To apply gradient descent, you need partial derivatives of the loss with respect to each one. With 10 features that is 11 separate update equations, and with 1,000 features it is 1,001. Writing them out individually does not scale. The solution is to derive a single **vectorized update rule** that handles all $k$ coefficients in one matrix operation.

---

## Deriving the Vectorized Update Rule

### Loss Function

We use Mean Squared Error (MSE) loss averaged over all $n$ training rows:

$$L(\beta_0, \boldsymbol{\beta}) = \frac{1}{n} \sum_{i=1}^n \left(y_i - \hat{y}_i\right)^2$$

where $\boldsymbol{\beta} = [\beta_1, \beta_2, \ldots, \beta_k]^T$ is the coefficient vector. Whether you use MSE or SSE (sum, not mean) does not change which $\boldsymbol{\beta}$ minimizes the loss, only the scale of the gradient. We use MSE here to keep gradient magnitudes independent of dataset size.

### Folding the Intercept In: One Vector of $k + 1$ Parameters

It's tempting to treat $\beta_0$ as a special case since it isn't multiplied by any feature. But recall the augmented-matrix trick from [Ch.6](/machine-learning-algorithms/ch6-multiple-linear-regression-math#matrix-form-of-the-equation): prepend a column of 1s to $X_{\text{train}}$, so every row picks up an extra entry $x_{i0} = 1$. The prediction equation becomes:

$$\hat{y}_i = \sum_{j=0}^k \beta_j x_{ij}, \qquad x_{i0} = 1 \text{ for every row } i$$

With that column in place, $\beta_0$ is no longer conceptually different from $\beta_1, \dots, \beta_k$, it's just the coefficient tied to a column that happens to always equal 1. There's one parameter vector $\boldsymbol{\beta} = [\beta_0, \beta_1, \ldots, \beta_k]^T$ of length $k + 1$, and one derivation covers all of it at once.

### Partial Derivative with Respect to Any Coefficient $\beta_j$

Apply the chain rule to the MSE sum. Since $\frac{\partial \hat{y}_i}{\partial \beta_j} = x_{ij}$, for any $j$ from $0$ to $k$:

$$\frac{\partial L}{\partial \beta_j} = -\frac{2}{n} \sum_{i=1}^n (y_i - \hat{y}_i) \cdot x_{ij}$$

Written out in full, this is a dot product between the residual vector $(\mathbf{y} - \hat{\mathbf{y}})$ and the $j$-th column of $X_{\text{train}}$. Intuitively, this says: look at every row where feature $j$ was large and the model under- or over-predicted, and check whether the two line up. If large values of feature $j$ tend to occur alongside large positive residuals, nudging $\beta_j$ up would shrink those errors, so the gradient for $\beta_j$ comes out large and positive too. If feature $j$'s values have nothing to do with the sign of the residual, the products mostly cancel out and the gradient stays near zero, meaning that coefficient barely needs to move. The dot product is just this "does this column track the error" check, computed for every row and summed in one shot.

Plug in $j = 0$ and this same formula recovers the intercept update without any extra derivation: since $x_{i0} = 1$ for every row, the sum collapses to $-\frac{2}{n} \sum_i (y_i - \hat{y}_i) = -2 \cdot \text{mean}(\mathbf{y} - \hat{\mathbf{y}})$, the negative average residual. It isn't a separate rule, it's this general rule with a column of constants plugged in.

The key insight: **the derivative for $\beta_j$ multiplies the residuals by the $j$-th column of the augmented $X_{\text{train}}$, intercept column included.** Gradient descent needs this derivative for every column, $j = 0, \ldots, k$. Computing them one at a time would require $k + 1$ separate dot products. Computing them all at once is a single matrix operation.

### Vectorizing All $k + 1$ Updates at Once

Stacking all $k + 1$ partial derivatives into a vector:

$$\nabla_{\boldsymbol{\beta}} L = \begin{bmatrix} \frac{\partial L}{\partial \beta_0} \\ \frac{\partial L}{\partial \beta_1} \\ \vdots \\ \frac{\partial L}{\partial \beta_k} \end{bmatrix} = -\frac{2}{n} \begin{bmatrix} \sum_i (y_i - \hat{y}_i) x_{i0} \\ \sum_i (y_i - \hat{y}_i) x_{i1} \\ \vdots \\ \sum_i (y_i - \hat{y}_i) x_{ik} \end{bmatrix}$$

Each row $j$ is $\sum_i (y_i - \hat{y}_i) x_{ij}$. That is exactly the matrix product of $X_{\text{train}}^T$ (shape $(k+1) \times n$, once the 1s column is included) with the residual column vector $(\mathbf{y} - \hat{\mathbf{y}})$ (shape $n \times 1$), giving a $(k+1) \times 1$ result:

$$\nabla_{\boldsymbol{\beta}} L = -\frac{2}{n} \, X_{\text{train}}^T \cdot (\mathbf{y} - \hat{\mathbf{y}})$$

In code, `np.dot(X_train.T, residuals)` (or equivalently `residuals @ X_train` when residuals is a 1D array, using NumPy's broadcasting) gives a vector of length $k + 1$, one gradient per coefficient including the intercept. The full vectorized update rule at each epoch is:

$$\boldsymbol{\beta}^{(\text{new})} = \boldsymbol{\beta} - \eta \cdot \left(-\frac{2}{n} \, X_{\text{train}}^T \cdot (\mathbf{y} - \hat{\mathbf{y}})\right)$$

This replaces $k + 1$ scalar equations, intercept included, with a single line of NumPy. The loop body does not grow as $k$ grows.

> **Why the code below still splits `intercept_` out separately:** Mathematically, $\beta_0$ is just row 0 of the same vector, that's the whole point of the augmented-matrix trick above. But NumPy code doesn't need to physically prepend a 1s column to get that benefit: $\sum_i (y_i - \hat{y}_i) \cdot 1$ is just `np.mean(residuals)`, so the intercept update can be computed directly without ever materializing the extra column. The `GDRegressor` class below does exactly that, one line for the intercept, one matrix operation for the rest, which is algebraically identical to running the single augmented update above and then splitting the result back into $\beta_0$ and $\boldsymbol{\beta}$.

### Why This Works: The Matrix Multiplication Intuition

To see concretely why $X_{\text{train}}^T \cdot (\mathbf{y} - \hat{\mathbf{y}})$ gives all $k + 1$ derivatives at once, consider a tiny example with $n = 2$ samples and $k = 2$ features, augmented column included:

$$X_{\text{train}} = \begin{bmatrix} 1 & x_{11} & x_{12} \\ 1 & x_{21} & x_{22} \end{bmatrix}, \quad \mathbf{r} = \begin{bmatrix} y_1 - \hat{y}_1 \\ y_2 - \hat{y}_2 \end{bmatrix}$$

$$X_{\text{train}}^T \cdot \mathbf{r} = \begin{bmatrix} 1 & 1 \\ x_{11} & x_{21} \\ x_{12} & x_{22} \end{bmatrix} \begin{bmatrix} r_1 \\ r_2 \end{bmatrix} = \begin{bmatrix} r_1 + r_2 \\ x_{11} r_1 + x_{21} r_2 \\ x_{12} r_1 + x_{22} r_2 \end{bmatrix}$$

Row 0 of the result is $r_1 + r_2 = \sum_i r_i$, exactly $\frac{\partial L}{\partial \beta_0}$ (up to the $-2/n$ factor). Row 1 is $\sum_i r_i x_{i1}$, the derivative for $\beta_1$, and row 2 is $\sum_i r_i x_{i2}$, the derivative for $\beta_2$. For $k = 10$ or $k = 10{,}000$, the same `@` operator handles all $k + 1$ of them, intercept included, in one call. This is the payoff of understanding the matrix structure of linear regression.

## Implementing `GDRegressor` from Scratch

The implementation below follows the [source notebook `batch-gradient-descent.ipynb`](https://github.com/campusx-official/100-days-of-machine-learning/blob/main/day52-types-of-gradient-descent/batch-gradient-descent.ipynb) exactly.

### Loading the Diabetes Dataset

```python
from sklearn.datasets import load_diabetes
import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.metrics import r2_score
from sklearn.model_selection import train_test_split

X, y = load_diabetes(return_X_y=True)
print(X.shape)  # (442, 10)
print(y.shape)  # (442,)
```

The dataset has 442 patients, each described by 10 standardized clinical features (age, sex, BMI, blood pressure, and six serum measurements). The target is a quantitative measure of diabetes progression one year after baseline. Crucially, sklearn's `load_diabetes` already returns normalized features, so no additional scaling step is needed here.

```python
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, random_state=2
)
print(X_train.shape)  # (353, 10)
```

### Benchmarking with sklearn's LinearRegression

Before building our own optimizer, we establish the OLS ceiling:

```python
reg = LinearRegression()
reg.fit(X_train, y_train)

y_pred = reg.predict(X_test)
print("OLS intercept:", reg.intercept_)
# 151.88331005254165

print("OLS coef_:", reg.coef_)
# [ -9.16, -205.46,  516.69,  340.62, -895.55,
#   561.22,  153.89,  126.73,  861.13,   52.42]

print("OLS R2:", r2_score(y_test, y_pred))
# 0.4399
```

The OLS model explains about 44% of the variance in test disease progression scores. This is our target to approach.

### The `GDRegressor` Class

```python
class GDRegressor:
    def __init__(self, learning_rate=0.5, epochs=1000):
        self.lr = learning_rate
        self.epochs = epochs
        self.coef_ = None
        self.intercept_ = None

    def fit(self, X_train, y_train):
        # Initialize: intercept to 0, all coefficients to 1
        self.intercept_ = 0
        self.coef_ = np.ones(X_train.shape[1])

        for _ in range(self.epochs):
            # Forward pass: compute predictions
            y_hat = X_train @ self.coef_ + self.intercept_

            # Intercept gradient: -2 * mean(residuals)
            intercept_der = -2 * np.mean(y_train - y_hat)
            self.intercept_ -= self.lr * intercept_der

            # Coefficient gradient: -2/n * X_train.T @ residuals
            coef_der = -2 * np.dot((y_train - y_hat), X_train) / X_train.shape[0]
            self.coef_ -= self.lr * coef_der

    def predict(self, X):
        return X @ self.coef_ + self.intercept_
```

A few design details worth noting:

**Initialization strategy.** The intercept starts at zero because it is a single scalar and zero is a neutral starting point. The coefficients are initialized to ones (`np.ones(X_train.shape[1])`), which avoids the symmetry-breaking problem of all-zeros initialization while remaining simple. The number of coefficients is inferred from `X_train.shape[1]` at fit time, so the class works for any number of features without modification.

**`np.dot((y_train - y_hat), X_train)`** computes the dot product of a 1D residual array (shape `(n,)`) with a 2D matrix (shape `(n, k)`), yielding a 1D result of shape `(k,)`. NumPy lines up the residual array against the matrix's first axis (the $n$ rows) and sums over that axis for each of the $k$ columns independently, which is exactly the "multiply residuals by one feature column and sum" computation from the derivation above, done for all $k$ columns at once. This is equivalent to `X_train.T @ residuals` (transpose to shape $(k, n)$, then matrix-multiply by the residual vector), but skips the explicit transpose.

**Simultaneous update.** Both `intercept_der` and `coef_der` are computed from the same `y_hat` at the start of the epoch, before either parameter is modified. This is important: if you updated the intercept first and then recomputed `y_hat` to get the coefficient gradient, the two updates would be using different parameter states, which is not the standard gradient descent algorithm.

### Running and Evaluating

```python
gd = GDRegressor(learning_rate=0.5, epochs=1000)
gd.fit(X_train, y_train)

print("GD intercept:", gd.intercept_)
# 152.01352

print("GD coef_:", gd.coef_)
# [ 14.39, -173.73,  491.55,  323.92, -39.33,
#  -116.01, -194.04,  103.38,  451.63,   97.57]

y_pred_gd = gd.predict(X_test)
print("GD R2:", r2_score(y_test, y_pred_gd))
# 0.4535
```

The custom `GDRegressor` achieves **R² = 0.4535 on the test set**, slightly above the OLS benchmark of 0.4399. The intercept converges to 152.01, close to OLS's 151.88. Most coefficients agree in sign and rough magnitude (negative $\beta_2$, large positive $\beta_3$ and $\beta_4$), but three flip sign entirely: $\beta_1$, $\beta_6$, and $\beta_7$. $\beta_1$ (`age`) is near zero in both models, so its flip is noise around a coefficient that barely matters. $\beta_6$ (`s2`) and $\beta_7$ (`s3`) are each strongly correlated with a third feature, $\beta_8$ (`s4`), with $r = 0.66$ and $r = -0.74$ respectively. That shared correlation flattens the loss surface along the directions those coefficients control: many different $(\beta_6, \beta_7, \beta_8)$ combinations produce nearly the same predictions, so the exact split OLS computes and the split 1000 epochs of gradient descent has reached can differ substantially, even in sign, without the R² score moving much. With more epochs or a finer learning rate sweep, the two solutions would align more closely.

## What Makes This "Batch" Gradient Descent

The word "batch" in "Batch Gradient Descent" refers to the fact that **every single epoch processes all $n$ training rows before taking one parameter update step**.

In the `fit` loop above, `y_hat = X_train @ self.coef_ + self.intercept_` computes predictions for all 353 training rows at once. The gradient `coef_der` is averaged over all 353 residuals. Only then do the parameters move. This is the defining characteristic of batch gradient descent: one gradient computation per epoch, using the full dataset.

The alternative approaches, Stochastic Gradient Descent (SGD) and Mini-Batch Gradient Descent, change precisely this one aspect: how many rows are used per gradient estimate and update step. The mathematical form of the update rule, the chain rule derivation, and the parameter initialization are all identical. The entire difference is in the loop body:

| Variant | Rows used per update | Updates per epoch |
| :--- | :--- | :--- |
| **Batch GD** (this post) | All $n$ rows | 1 |
| Stochastic GD | 1 row | $n$ |
| Mini-Batch GD | $b$ rows (batch size) | $n / b$ |

For the diabetes dataset with $n = 353$ training rows, batch GD takes 1 update per epoch. Stochastic GD would take 353 updates per epoch, one per row. Mini-Batch GD with batch size 32 would take about 11 updates per epoch.

The practical implication: batch GD is the safest choice when the dataset fits in memory and the loss surface is convex (guaranteed for linear regression's squared error). When the dataset is large or the loss is non-convex, SGD or mini-batch GD become preferable because they provide noisier but more frequent gradient signals.

## Summary & Key Takeaways

1. **Extending to $k$ features**: Multiple linear regression requires $k + 1$ parameters ($k$ slopes plus one intercept). Gradient descent applies the same chain rule to each, producing $k + 1$ update equations per epoch.
2. **The intercept isn't special**: with a column of 1s prepended to $X_{\text{train}}$ (the Ch.6 augmented-matrix trick), $\beta_0 \leftarrow \beta_0 - \eta \cdot \left(-2 \cdot \text{mean}(\mathbf{y} - \hat{\mathbf{y}})\right)$ is just the general $\beta_j$ update with $x_{i0} = 1$ plugged in, not a separately derived rule.
3. **Vectorized update for all $k + 1$ parameters**: $\boldsymbol{\beta} \leftarrow \boldsymbol{\beta} - \eta \cdot \left(-\frac{2}{n} X_{\text{train}}^T (\mathbf{y} - \hat{\mathbf{y}})\right)$. The matrix transpose $X_{\text{train}}^T$ turns the per-residual, per-column products into a single dot product that yields all $k + 1$ gradients simultaneously, intercept included.
4. **Why transposing works**: $X_{\text{train}}^T \cdot \mathbf{r}$ produces a $(k+1)$-dimensional vector where entry $j$ is $\sum_i r_i x_{ij}$, exactly the sum needed for $\frac{\partial L}{\partial \beta_j}$. The transpose swaps rows and columns so each feature's (and the intercept's constant "feature") values end up in a row, enabling a single matrix-vector multiply.
5. **Initialization**: Intercept to 0, coefficients to ones. The shape of the coefficient array is inferred from `X_train.shape[1]` at fit time, making the class feature-count agnostic.
6. **Simultaneous update**: Both gradients are computed from the same `y_hat` before either parameter is updated. Updating intercept first and recomputing `y_hat` mid-epoch would violate the standard gradient descent algorithm.
7. **Batch GD result on diabetes**: With `learning_rate=0.5` and `epochs=1000`, the custom `GDRegressor` achieves test R² = 0.4535, modestly above OLS's 0.4399. Seven of ten coefficients agree in sign; the three that flip include a near-zero coefficient and two strongly collinear features whose individual OLS values are unstable. More epochs would close the remaining magnitude gap.
8. **What "batch" means**: Every epoch consumes all $n$ training rows before taking one gradient step. This is the defining property that distinguishes batch GD from its faster, noisier variants.
